# 방송 플랫폼 소개 영상 스크립트

- 형식: 유튜브 가로 영상(1920×1080). 장면은 HyperFrames로 만들고, 내레이션은 Edge TTS `ko-KR-SunHiNeural`(여성)로 읽는다.
- 길이: 8분 33초(2026-11-12 게시본, https://youtu.be/_8Z5iwoGOKY). 제작 도구와 원본은 저장소 밖 `C:/projects/chzzz-video`에 있다.
- 약어는 내레이션에 영문(HTTPS, API, PostgreSQL, CSRF, WebRTC, 미디어 MTX)으로 적는다. 한글로 이어 적으면 TTS가 잘못 읽는다.
- 서비스 이름: 영상 안에서는 **방송 플랫폼**으로 부른다. 내레이션·자막·화면 어디에도 저장소 이름과 주소를 넣지 않는다. 저장소 주소는 맨 아래 **영상 설명** 마지막 줄에만 넣는다.
- 쓰지 않는 소재: 휴대폰·PC로 찍은 실제 송출·시청 장면(캡처 포함). 라이브 화면은 HyperFrames로 그린 UI 목업과 도식으로만 보여 준다. 영상 칸은 회색 자리 표시(`라이브 영상`)로 둔다.
- 결제: 테스트 카드 결제는 진행하지 않았다. 결제 완료 화면은 보여 주지 않고, 해당 장면에 `결제 테스트 진행하지 않음` 표기를 붙인다.

## 쓰는 방법

- 장면마다 표 한 줄이 내레이션 한 문장이다. **내레이션** 칸을 위에서 아래로 이어 붙이면 그 장면의 TTS 입력이 된다.
- **화면** 칸은 그 문장이 읽히는 동안 일어나는 동작이고, **자막** 칸은 화면 아래에 띄우는 짧은 문구다. 설명하는 대상이 문장마다 화면이나 자막에 보이도록 짝을 맞췄다.
- 내레이션은 지시어(이것, 그, 여기 등)를 쓰지 않고 대상의 이름을 그대로 부른다. 영문 약어는 읽는 소리대로 한글로 적고, 자막에는 원래 표기를 쓴다.

## 공통 소재: 구조도

S02~S05, S08, S10에서 **같은 구조도 한 장**을 계속 다시 띄우고, 장면마다 필요한 상자와 화살표만 밝게 강조한다. 처음 보는 사람이 "지금 구조도의 어디를 말하는지"를 놓치지 않게 하려는 것이다.

```text
 [PC 브라우저] ──http://localhost:3000──▶ [frontend: React + nginx] ──/api──▶ [backend: Spring Boot + Kotlin] ──▶ [db: PostgreSQL]
                                                                                   │      ▲                          
 [휴대폰 브라우저] ──https://PC-IP:8443──▶ [caddy: HTTPS] ──/media──▶ [mediamtx: WebRTC] ┘      └──▶ [토스페이먼츠 API (테스트)]
                                         └──────── 화면·/api ────────▶ frontend                        
```

- 상자 색: 사용자 기기(회색), 컨테이너 5개(파랑), 바깥 서비스(주황).
- 강조 방식: 강조할 상자는 테두리를 두껍게 하고 나머지는 40% 투명도로 흐리게 한다. 흐름은 점이 따라 움직이는 화살표로 그린다.

| 구조도: `backend` 강조 | backend: 로그인·권한 검사와 방송·댓글·후원 처리 | 두 번째 컨테이너는 스프링 부트와 코틀린으로 만든 백엔드 서버입니다. |

## S03 아키텍처 ② 요청이 흐르는 길 (1:25–2:35)

S02와 같은 구조도를 세 번 다시 띄우고, 흐름마다 화면 위쪽 탭(`녹화방송` · `라이브` · `후원`)이 바뀐다.

| 화면 | 자막 | 내레이션 |
| --- | --- | --- |
| 구조도 전체가 흐려진 채 위쪽 탭 세 개가 나타난다 | 녹화방송 · 라이브 · 후원 요청이 어느 컨테이너를 지나는지 | 요청이 흐르는 길을 녹화방송, 라이브, 후원 세 가지로 보겠습니다. |
| 탭 `녹화방송`. PC → frontend → backend 화살표, backend 옆에 `디스크(영상 파일)`와 `db(제목·등록일시)` 두 갈래 | backend가 영상 파일은 디스크에, 제목·등록 일시는 db에 저장 | 녹화방송의 영상 파일은 백엔드의 디스크에, 제목과 등록 일시는 데이터베이스에 저장됩니다. |
| backend → PC 화살표 위에 영상 막대가 조각으로 나뉘어 전달되는 애니메이션, 라벨 `Range 요청 · 206` | 영상 전체가 아니라 보는 부분만 받아서 바로 건너뛰기 가능 | 재생할 때는 레인지 요청으로 필요한 부분만 보내서, 재생 위치를 바로 옮길 수 있습니다. |
| 탭 `라이브`. 휴대폰 → caddy → mediamtx 화살표, 라벨 `WHIP 송출` | 휴대폰 영상이 caddy를 거쳐 mediamtx로 올라감(송출) | 라이브 방송에서 휴대폰은 WebRTC의 윕 방식으로 영상을 미디어 MTX에 보냅니다. |
| mediamtx → PC 화살표, 라벨 `WHEP 시청` | mediamtx의 영상이 frontend를 거쳐 시청자 브라우저로 내려감(시청) | 시청자의 브라우저는 웹 방식으로 미디어 MTX에서 영상을 받아 봅니다. |
| mediamtx → backend 점선 화살표, 말풍선 `송출 키 확인` → `허가` | mediamtx가 backend에 "이 송출 키로 방송해도 되나요?" 확인 | 미디어 MTX는 송출 요청마다 백엔드에 송출 키를 확인합니다. |
| mediamtx → backend 점선 화살표 `영상 들어옴` / `영상 끊김`, backend 옆 상태 배지가 `대기 → 방송 중 → 종료`로 바뀜 | 영상이 들어오고 끊길 때마다 backend가 방송 상태를 바꿈 | 영상이 들어오거나 끊기면 미디어 MTX가 백엔드에 알리고, 백엔드는 방송 상태를 대기, 방송 중, 종료로 바꿉니다. |
| 탭 `후원`. PC → backend `주문 생성` 화살표 | backend가 후원 금액과 받을 방송자를 먼저 정해 주문을 만듦 | 후원에서는 백엔드가 먼저 금액과 받는 방송자를 정해 주문을 만듭니다. |
| backend ↔ 토스 상자 화살표, 라벨 `승인 확인` → 체크 표시 `확정` | backend가 토스에 승인 여부를 물어 본 뒤에만 후원을 확정 | 결제가 끝나면 백엔드가 토스 승인 API로 결제를 확인한 뒤에만 후원을 확정합니다. |
| 토스 → backend 화살표 `웹훅`, 웹훅 봉투에 X 표시 후 backend → 토스 `조회` 화살표 | 토스가 보낸 알림도 backend가 토스에 다시 물어서 확인 | 토스의 웹훅 알림도 그대로 믿지 않고, 백엔드가 조회 API로 다시 확인합니다. |

| `curl` 터미널 목업에 `401`, `403` 두 줄이 찍힌다 | API를 직접 불러도 같은 결과 | 화면을 거치지 않고 API를 직접 불러도 결과는 같습니다. |
