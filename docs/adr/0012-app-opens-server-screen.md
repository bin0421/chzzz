# 앱은 빌드한 화면을 넣지 않고 서버 주소의 화면을 앱 창에서 연다

6단계는 Windows용 데스크톱 앱(Electron, exe)과 Android 앱(Capacitor, apk)을 만든다. 앱 안에 무엇을 띄울지 정해야 한다. `frontend/`를 빌드해 앱에 넣으면 화면은 앱 내부 출처(`file://`, `https://localhost` 등)에서 뜨고, API는 다른 출처인 서버로 간다.

앱은 처음 실행할 때 사용자에게 **서버 주소**를 받아 출처(`https://호스트[:포트]`, 같은 PC는 `http://localhost[:포트]`)만 저장하고, 그 뒤로는 그 주소의 화면을 앱 창에서 그대로 연다. 화면과 API가 웹과 같은 출처에 있으므로 세션 쿠키(ADR-0005), CSRF 토큰, 토스 결제 성공·실패 주소(ADR-0007)가 웹과 똑같이 동작하고 `frontend/`·`backend/`를 바꾸지 않는다.

- **시작 화면**(`apps/shell/`): 서버 주소 입력·검증, 연결 확인, 연결 실패 화면만 가진 작은 정적 화면이다. 두 앱이 같은 파일을 쓴다. 프레임워크 없이 TypeScript + Vite로 만든다.
- **연결 확인**: 저장하기 전에 `/api/auth/me`가 200(로그인됨) 또는 401(로그인 안 됨)인지 본다. 시작 화면 출처에서 서버로 직접 요청하면 CORS에 막히므로(서버는 CORS 헤더를 주지 않는다) 요청은 앱이 대신 하고(데스크톱은 메인 프로세스의 `net.fetch`), 시작 화면은 상태 코드만 받아 해석한다.
- **앱 다리**: 데스크톱은 preload가 시작 화면(`file://`)에만 `window.chzzzApp`을 열고, 메인 프로세스도 시작 화면에서 온 요청만 받는다. 서버 화면에는 아무것도 노출하지 않는다.
- **권한**: 카메라·마이크(`media`)와 영상 전체 화면(`fullscreen`)만, 저장한 서버 출처에서 요청할 때만 허용한다. 나머지 권한과 다른 출처는 거절한다.
- **로그인 유지**: 쿠키는 앱 웹뷰의 영구 저장소(데스크톱은 기본 세션, 사용자 데이터 폴더)에 둔다. 서버의 `JSESSIONID`는 만료 시각이 없는 세션 쿠키라 Chromium이 앱을 닫을 때 버린다. 서버를 바꾸지 않고, 데스크톱 앱이 저장한 서버 호스트의 세션 쿠키가 생기면 같은 값에 30일 만료를 붙여 다시 저장한다. 로그인이 실제로 유효한지는 그대로 서버 세션(유휴 만료·로그아웃)이 정한다.
- **연결 실패**: 서버 화면을 열 때 캐시를 다시 확인한다(`Cache-Control: no-cache`, "다시 불러오기"는 캐시 무시). 그러지 않으면 서버가 꺼져 있어도 캐시에 남은 `index.html`이 떠 연결 실패 화면 대신 빈 목록이 보인다.
- **판단 로직**: 주소 검증, 연결 확인 해석, 권한 판단은 Electron 없이 도는 순수 모듈로 두고 Vitest로 테스트한다.

## Considered Options

- **빌드한 프론트를 앱에 넣기**: 서버가 꺼져 있어도 첫 화면은 뜨지만, 출처가 갈라져 세션 쿠키 `SameSite`, CORS 자격 증명 허용, CSRF 토큰 전달, 토스 결제 후 돌아올 주소(딥링크)를 모두 다시 설계해야 한다. ADR-0005·0007을 다시 열고 서버도 바꿔야 한다. 앱 업데이트와 서버 배포의 화면 버전도 따로 맞춰야 한다.
- **서버 주소를 앱에 미리 넣기**: 입력 단계가 없지만 이 과제의 서버는 실행하는 PC마다 LAN 주소가 다르고 클라우드 서버가 없다.
- **시작 화면 없이 주소만 묻는 기본 대화상자**: 연결 확인과 연결 실패 화면을 두 앱에서 따로 만들어야 한다.

## Consequences

- 앱은 서버가 닿아야 쓸 수 있다. 닿지 않으면 연결 실패 화면에서 "다시 시도"나 "서버 주소 변경"을 고른다.
- 화면을 고치면 서버만 다시 배포하면 되고 앱은 다시 만들지 않아도 된다.
- 데스크톱 앱의 로그인 쿠키는 앱을 닫아도 디스크(사용자 데이터 폴더)에 남는다. 브라우저 탭을 닫으면 사라지는 웹과 다르지만, 서버 세션이 만료되거나 로그아웃하면 그 쿠키로는 로그인되지 않는다.
- 서버의 HTTPS 인증서(Caddy 로컬 CA)는 앱이 기본으로 신뢰하지 않는다. 처음 연결할 때 지문을 확인해 고정하는 방식은 ADR-0013에서 다룬다.
- 저장한 서버 출처 밖으로 가는 이동·새 창(외부 링크, 토스 결제창 도메인)을 어디서 열지는 6단계 02에서 정한다.
