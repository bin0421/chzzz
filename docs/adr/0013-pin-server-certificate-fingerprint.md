# 앱은 처음 연결할 때 서버 인증서 지문을 확인받아 그 출처에 고정한다

앱이 여는 서버 주소는 `https://<PUBLIC_HOST>:8443`이고, 인증서는 Caddy가 직접 만든 로컬 CA로 서명한다(ADR-0004). 앱 웹뷰는 이 인증서를 신뢰하지 않으므로 그냥 열면 연결이 끊긴다. 브라우저처럼 "위험을 감수하고 계속" 버튼을 줄 수도 없고, 인증서 검사를 끄면 같은 네트워크의 누구든 서버인 척할 수 있다.

앱은 **처음 연결할 때 서버 주소와 서버 인증서의 SHA-256 지문을 보여 주고**, 사용자가 신뢰하면 그 **(출처, 지문)** 조합만 **신뢰한 인증서**로 앱 저장소(데스크톱은 사용자 데이터 폴더의 `settings.json`)에 둔다. 다음부터 같은 출처에서 같은 지문이면 묻지 않는다.

판단 규칙(순수 모듈 `apps/desktop/src/trust.ts`, Android도 같은 표):

| 인증서 오류가 난 주소 | 저장된 신뢰 기록 | 결과 |
| --- | --- | --- |
| 저장한 서버 출처 | 같은 지문 | 받아들인다 |
| 저장한 서버 출처 | 없음 | 주소·지문을 보여 주고 묻는다 |
| 저장한 서버 출처 | 다른 지문 | 경고와 함께 이전·새 지문을 보여 주고 다시 묻는다 |
| 다른 출처(다른 호스트·포트·스킴, 결제위젯 등) | 상관없음 | 묻지 않고 거절한다 |
| (서버 주소를 저장하지 않음) | 상관없음 | 거절한다 |

- 출처는 스킴·호스트·포트까지 비교한다. 서버 주소를 바꾸면 새 출처의 기록만 보므로 다시 묻는다. 이전 출처의 기록은 그 출처에만 쓰인다.
- 지문은 서버가 보낸 서버 인증서(leaf) DER의 SHA-256을 `AB:CD:…` 형식으로 보여 준다. 브라우저의 인증서 보기와 같은 형식이라 서버 PC에서 비교할 수 있다.
- **데스크톱**: 화면·하위 요청은 Electron `certificate-error`에서 판단한다. 묻는 경우 연결하지 않고 시작 화면의 지문 확인 화면(`#trust`)을 연다. 저장하기 전 연결 확인(`/api/auth/me`)은 메인 프로세스 `net.fetch`가 인증서 오류로 실패하면 Node `https`로 인증서를 받아 같은 판단을 거친다(확인하려는 주소를 서버 출처로 본다). 시작 화면이 "신뢰"를 보내면 메인 프로세스는 그 지문이 실제로 보여 준 지문과 같을 때만 저장한다.
- **WebRTC 미디어**(DTLS)는 인증서 체인을 쓰지 않아 이 판단과 무관하다. WHIP/WHEP HTTP 요청은 같은 출처의 `/media`로 가므로 같은 규칙을 탄다.

## 고정하는 인증서와 Caddy 설정 변경

Caddy `tls internal` 기본값은 중간 CA가 **12시간짜리** 서버 인증서를 발급하고(약 8시간마다 갱신), 중간 CA도 7일마다 바뀐다. 루트 CA(10년)는 서버가 보내지 않는다. 이대로 서버 인증서 지문을 고정하면 앱이 하루에도 여러 번 "지문이 바뀌었다"고 묻는다.

그래서 Caddyfile을 `tls { issuer internal { lifetime 365d sign_with_root } }`로 바꿔 **루트 CA가 직접 1년짜리 서버 인증서를 발급**하게 하고, 앱은 그 서버 인증서 지문을 고정한다. 인증서와 CA는 `caddy-data` 볼륨에 남으므로 재시작해도 지문이 같다. 지문이 바뀌는 때는 갱신(유효기간의 약 2/3, 8개월쯤), `caddy-data` 초기화, `PUBLIC_HOST` 변경뿐이다. 브라우저·휴대폰 웹에서 보이는 경고는 그대로다(여전히 로컬 CA).

## Considered Options

- **기본 설정(12시간 인증서) 그대로 고정**: 서버를 바꾸지 않지만 하루에 여러 번 경고가 뜬다. 사용자가 경고에 무뎌져 진짜 바뀐 서버도 신뢰하게 된다.
- **Caddy 루트 CA 지문 고정**: 지문이 `caddy-data` 초기화 때만 바뀌지만, 서버가 루트 인증서를 보내지 않으므로 Caddy가 루트를 따로 내보내고 앱이 서버 체인의 서명을 직접 검증해야 한다. 앱 코드와 설명할 부분이 늘어난다.
- **인증서 검사 끄기 / 모든 인증서 받아들이기**: 구현은 가장 쉽지만 같은 네트워크의 누구든 서버인 척하고 로그인 쿠키를 가로챌 수 있다.
- **Caddy 루트 CA를 운영체제·기기 신뢰 저장소에 설치**: 앱 코드는 필요 없지만 사용자가 기기 보안 설정을 바꿔야 하고, 그 CA가 모든 사이트의 인증서를 만들 수 있게 된다.
- **공인 인증서(도메인 + Let's Encrypt)**: 이 과제는 도메인과 클라우드가 없다(범위 밖).

## Consequences

- 처음 연결할 때 사용자가 지문을 한 번 확인한다. 서버 PC에서 지문을 보는 방법은 README에 적는다.
- 1년 인증서가 갱신되거나 서버 데이터를 초기화하면 앱이 경고와 함께 다시 묻는다. 이 변경 전에 만든 `caddy-data`에는 12시간 인증서가 남아 있어, 그 인증서가 한 번 갱신될 때(최대 12시간 안) 1년 인증서로 바뀌며 한 번 더 묻는다.
- 서버 인증서 수명이 길어져 키가 새면 피해 기간이 길다. 로컬 LAN 확인용 과제 서버라 받아들인다.
- 저장한 서버가 아닌 곳의 잘못된 인증서는 묻지 않으므로, 결제위젯 같은 외부 도메인은 공인 인증서여야 열린다.
