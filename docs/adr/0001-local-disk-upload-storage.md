# 업로드 파일은 로컬 디스크에 두고 Range 요청으로 스트리밍한다

1단계에서 업로드 파일은 `RECORDING_STORAGE_DIR`로 지정한 로컬 디스크 폴더에 서비스가 정한 이름(UUID)으로 저장하고, DB에는 그 이름만 남긴다. 재생은 백엔드가 HTTP Range 요청을 지원하는 엔드포인트로 내려줘서 플레이어에서 탐색(seek)이 되게 한다. Docker Compose 볼륨으로 폴더를 유지하면 재시작 후에도 재생이 유지된다.

## Considered Options

- **MinIO(S3 호환)**: 실무에 가깝지만 1단계 범위에 비해 구성 요소와 실행 절차가 늘어난다.
- **DB BLOB**: 대용량 영상에서 DB가 비대해지고 스트리밍 처리가 어렵다.

## Consequences

2단계(라이브 방송 송출)에서 저장 방식을 다시 검토할 가능성이 크다. 저장소 접근은 인터페이스 뒤에 두어 교체할 수 있게 한다.
