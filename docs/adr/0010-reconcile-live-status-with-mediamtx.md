# 라이브 방송 상태를 시작 시 정리 대신 MediaMTX 송출과 주기적으로 대조해 정리한다

ADR-0003을 보완한다. 2~4단계의 백엔드는 시작할 때마다 대기·방송 중인 라이브 방송을 모두 종료로 바꿨다(`LiveBroadcastStartupCleanup`). 백엔드가 한 대일 때는 "재시작 = MediaMTX 연결도 끊김"이라 맞았지만, 5단계에서 HPA가 파드를 늘리면 새 파드가 뜰 때마다 다른 파드에서 진행 중인 방송까지 끝난다.

시작 시 정리를 없애고, 각 백엔드 인스턴스가 주기적으로(10초) MediaMTX 제어 API `GET /v3/paths/list`로 실제 송출 중인 경로(`available: true`)를 읽어 DB의 **방송 중**과 비교한다. 방송 중이 된 지 유예 시간(`LIVE_PUBLISH_GRACE`, 기본 30초)이 지났는데 목록에 없으면 종료로 정리한다. 이렇게 하면 전체 재시작·MediaMTX 재시작 뒤 남은 방송도 정리되고, 인스턴스가 늘어도 방송은 그대로다.

- **대기**는 대조하지 않는다. 지금처럼 대기 시간 초과(`LIVE_PENDING_TIMEOUT`)가 정리한다.
- **MediaMTX에 닿지 않으면**(연결 실패·오류 응답) 아무것도 종료하지 않고 경고 로그만 남긴다. 송출 여부를 모르는데 끊긴 것으로 보면, MediaMTX가 잠깐 재시작하는 동안 모든 방송이 끝나기 때문이다.
- **유예 시간**은 "영상 준비됨" 훅으로 방송 중이 된 직후 MediaMTX 목록 반영이 늦거나, 대조가 목록을 읽은 직후에 방송 중이 된 경우를 막는다.
- **여러 인스턴스**가 같은 대조를 동시에 돌려도 이미 종료된 방송은 다시 종료하지 않아 결과가 같다(분산 락 없음, 스펙 범위 밖).
- `MEDIAMTX_API_URL`이 비면 대조하지 않는다. 개발 실행(호스트의 `bootRun`)은 제어 API 포트가 공개되지 않아 닿지 않으므로 기본값을 비워 둔다. compose·Kubernetes는 `http://mediamtx:9997`을 쓴다.

## MediaMTX 제어 API 인증

MediaMTX는 `authMethod: http`일 때 제어 API 요청도 백엔드 인증 엔드포인트에 묻는다. 백엔드는 `publish`·`read`만 허가하므로 그대로 두면 대조 요청이 거절된다. `authHTTPExclude`에 `action: api`를 넣어 제어 API는 인증 없이 받고, 그 대신 9997 포트를 compose 내부 네트워크(Kubernetes에서는 ClusterIP Service)에만 둔다. 호스트 포트로 공개하지 않고, 앞단 프록시(Caddy, nginx, Vite)도 넘기지 않는다.

## Considered Options

- **시작 시 정리 유지 + 인스턴스별 소유 표시**: 방송마다 처리한 인스턴스를 기록해 자기 것만 정리한다. 하지만 MediaMTX 훅은 아무 인스턴스로나 가므로 "소유 인스턴스"가 의미가 없고, 인스턴스가 줄어 사라지면 남은 방송을 정리할 주체가 없다.
- **시작 시 정리를 없애고 끊김 훅·대기 시간 초과에만 맡기기**: 가장 단순하지만, 백엔드·MediaMTX가 함께 재시작되어 끊김 훅을 놓친 방송은 영원히 방송 중으로 남는다.
- **제어 API도 백엔드 인증으로 허가(공유 비밀번호)**: 백엔드가 Basic 인증으로 비밀번호를 보내고 인증 엔드포인트가 `api` 동작을 그 비밀번호로 허가한다. 내부망 안의 다른 프로세스도 막을 수 있지만, 비밀값 하나와 인증 규칙이 늘어난다. 이 과제는 내부망을 신뢰 경계로 두므로(`/internal/mediamtx/*` 훅과 같은 전제) 포트를 내부에만 두는 쪽을 골랐다.

## Consequences

- 송출 탭을 닫았는데 끊김 훅이 오지 않아도 늦어도 유예 시간 + 대조 주기(약 40초) 안에 종료된다.
- 전체 재시작 뒤 남아 있던 방송 중은 첫 대조(시작 후 약 10초)에서, 대기는 대기 시간 초과로 종료된다. 시작 직후 잠깐은 방송 중으로 보일 수 있다.
- 내부망에서 9997 포트에 닿는 프로세스는 MediaMTX 설정 변경·세션 끊기 같은 제어 API를 쓸 수 있다. 내부망을 신뢰한다는 전제가 깨지면 위 "공유 비밀번호" 방식으로 바꾼다.
