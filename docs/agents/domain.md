# 도메인 문서

엔지니어링 스킬이 코드베이스를 탐색할 때 이 저장소의 도메인 문서를 어떻게 사용하는지 정한다.

## 탐색 전에 읽을 것

- 루트의 **`GLOSSARY.md`**
- **`docs/adr/`**: 작업할 영역에 해당하는 ADR

이 파일들이 없으면 **조용히 진행한다**. 없다고 지적하거나 미리 만들자고 제안하지 않는다. 용어나 결정이 실제로 확정될 때 `/domain-modeling` 스킬(`/grill-with-docs`, `/improve-codebase-architecture`를 통해 호출)이 필요한 시점에 만든다.

## 파일 구조

단일 컨텍스트:

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-....md
│   └── 0002-....md
└── (backend/, frontend/ 등)
```

## 글로서리의 어휘를 쓴다

결과물(이슈 제목, 리팩터 제안, 가설, 테스트 이름)에서 도메인 개념을 부를 때는 `GLOSSARY.md`에 정의된 용어를 쓴다. 글로서리가 피하라고 명시한 동의어로 옮겨 가지 않는다.

필요한 개념이 글로서리에 없다면 신호다. 프로젝트가 쓰지 않는 말을 지어내고 있거나(다시 생각한다) 실제 빈틈이 있는 것이다(`/domain-modeling`용으로 기록한다).

## ADR 충돌은 드러낸다

결과물이 기존 ADR과 어긋나면 조용히 덮어쓰지 말고 명시한다:

> _ADR-0002(PostgreSQL 사용)와 어긋나지만, ... 때문에 다시 검토할 가치가 있다_
