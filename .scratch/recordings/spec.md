# 1단계: 녹화방송 등록·시청

## Problem Statement

방송을 다시 보고 싶은 사람과 지난 방송을 공유하고 싶은 사람이 있다. 지금은 녹화된 방송 영상을 한곳에 모아 등록하고, 목록에서 골라 바로 재생할 수 있는 곳이 없다. 계정을 만들거나 로그인하는 절차는 이 단계에서 부담만 된다. 등록한 녹화방송은 서비스가 재시작되어도 사라지면 안 된다.

## Solution

로그인 없이 누구나 쓸 수 있는 웹 서비스를 만든다.

- 등록 화면에서 **제목**과 **영상 출처**를 입력해 **녹화방송**을 등록한다. 영상 출처는 **업로드 파일**(mp4/webm)이나 **외부 URL**(브라우저가 바로 재생할 수 있는 영상 파일 주소) 중 하나다.
- 목록 화면에서 등록된 녹화방송을 최신순으로 본다.
- 상세 화면에서 녹화방송의 정보를 보고 플레이어로 재생하며, 원하는 위치로 탐색한다.
- 녹화방송 메타데이터와 업로드 파일은 서비스를 재시작해도 남는다.

## User Stories

### 등록

1. 시청자로서, 로그인하지 않고 녹화방송을 등록하고 싶다. 계정 없이 바로 공유할 수 있도록.
2. 등록자로서, 녹화방송에 제목을 붙이고 싶다. 목록에서 알아볼 수 있도록.
3. 등록자로서, 내 컴퓨터의 영상 파일을 업로드해서 녹화방송을 등록하고 싶다. 영상을 따로 호스팅하지 않아도 되도록.
4. 등록자로서, 이미 인터넷에 올라가 있는 영상 파일 주소로 녹화방송을 등록하고 싶다. 큰 파일을 다시 올리지 않아도 되도록.
5. 등록자로서, 등록 화면에서 업로드 파일과 외부 URL 중 무엇을 쓸지 고르고 싶다. 고른 쪽 입력란만 보여서 헷갈리지 않도록.
6. 등록자로서, 제목을 비우거나 공백만 넣으면 안내를 받고 싶다. 이름 없는 녹화방송이 생기지 않도록.
7. 등록자로서, 제목이 100자를 넘으면 안내를 받고 싶다. 목록이 깨지지 않도록.
8. 등록자로서, 제목 앞뒤의 공백은 자동으로 정리되면 좋겠다. 실수로 넣은 공백이 남지 않도록.
9. 등록자로서, 파일도 URL도 넣지 않으면 안내를 받고 싶다. 재생할 수 없는 녹화방송이 생기지 않도록.
10. 등록자로서, `http`/`https`가 아닌 주소를 넣으면 안내를 받고 싶다. 잘못된 주소를 바로 고칠 수 있도록.
11. 등록자로서, mp4/webm이 아닌 파일을 올리면 안내를 받고 싶다. 브라우저에서 재생되지 않는 영상이 등록되지 않도록.
12. 등록자로서, 허용 크기(기본 500MB)를 넘는 파일을 올리면 안내를 받고 싶다. 업로드가 왜 실패했는지 알 수 있도록.
13. 등록자로서, 업로드가 진행되는 동안 등록 버튼이 비활성화되면 좋겠다. 같은 녹화방송을 두 번 등록하지 않도록.
14. 등록자로서, 등록에 성공하면 바로 그 녹화방송의 상세 화면으로 이동하고 싶다. 제대로 재생되는지 곧바로 확인할 수 있도록.
15. 등록자로서, 서버가 등록을 거절하면 그 이유를 화면에서 보고 싶다. 입력을 고쳐 다시 시도할 수 있도록.
16. 등록자로서, 이미 있는 녹화방송과 같은 제목이나 같은 URL로도 등록하고 싶다. 같은 이름의 다른 회차를 올릴 수 있도록.

### 목록

17. 시청자로서, 로그인하지 않고 녹화방송 목록을 보고 싶다. 바로 볼 만한 녹화방송을 고를 수 있도록.
18. 시청자로서, 목록이 최신 등록순이면 좋겠다. 새로 올라온 녹화방송을 먼저 볼 수 있도록.
19. 시청자로서, 목록의 각 항목에서 제목, 등록일시, 영상 출처 종류(업로드/URL)를 보고 싶다. 고르기 전에 무엇인지 알 수 있도록.
20. 시청자로서, 목록 항목을 누르면 상세 화면으로 가고 싶다. 바로 재생할 수 있도록.
21. 시청자로서, 등록된 녹화방송이 없으면 안내 문구와 등록 버튼을 보고 싶다. 빈 화면에서 무엇을 해야 할지 알 수 있도록.
22. 시청자로서, 어느 화면에서든 목록과 등록 화면으로 갈 수 있으면 좋겠다. 길을 잃지 않도록.

### 상세·재생

23. 시청자로서, 로그인하지 않고 녹화방송 상세 화면을 보고 싶다. 링크만으로 공유받은 녹화방송을 볼 수 있도록.
24. 시청자로서, 상세 화면에서 제목과 등록일시를 보고 싶다. 무엇을 보고 있는지 알 수 있도록.
25. 시청자로서, 상세 화면의 플레이어로 녹화방송을 재생, 일시정지하고 볼륨을 조절하고 싶다. 브라우저 기본 조작으로 편하게 볼 수 있도록.
26. 시청자로서, 업로드 파일로 등록된 녹화방송에서 원하는 위치로 탐색하고 싶다. 처음부터 다 받지 않고 보고 싶은 부분을 볼 수 있도록.
27. 시청자로서, 외부 URL로 등록된 녹화방송도 같은 플레이어로 보고 싶다. 출처와 상관없이 똑같이 볼 수 있도록.
28. 시청자로서, 영상을 재생할 수 없으면(외부 URL이 깨졌거나 형식이 맞지 않는 경우) 안내 문구를 보고 싶다. 화면이 멈춘 것처럼 보이지 않도록.
29. 시청자로서, 없는 녹화방송의 주소로 들어가면 "찾을 수 없음" 안내와 목록으로 가는 링크를 보고 싶다. 잘못된 링크에서 빠져나올 수 있도록.

### 영속성·운영

30. 운영자로서, 서비스를 재시작해도 등록된 녹화방송 메타데이터가 그대로 남기를 원한다. 사용자가 등록한 내용을 잃지 않도록.
31. 운영자로서, 서비스를 재시작해도 업로드 파일이 남아 계속 재생되기를 원한다. 메타데이터만 남고 영상이 사라지는 일이 없도록.
32. 운영자로서, DB 접속 정보, 업로드 파일 보관 위치, 최대 업로드 크기를 환경변수로 바꾸고 싶다. 환경마다 코드를 고치지 않도록.
33. 채점자로서, JDK와 Node를 설치하지 않고 명령 하나로 전체 서비스를 띄우고 싶다. 바로 확인할 수 있도록.
34. 개발자로서, DB만 컨테이너로 띄우고 백엔드와 프론트를 로컬에서 실행하고 싶다. 빠르게 고치고 확인할 수 있도록.
35. 채점자로서, README에서 실행 방법, 환경변수 예시, 구현 범위, 직접 확인 절차를 보고 싶다. 무엇이 구현되었고 어떻게 확인하는지 알 수 있도록.
36. 채점자로서, README의 절차대로 녹화방송을 등록하고 목록·상세·재생을 확인한 뒤 재시작하고 등록 정보가 남는지 확인하고 싶다. 요구사항 충족을 직접 검증할 수 있도록.

## Implementation Decisions

### 도메인

- **녹화방송**은 식별자, 제목, 영상 출처, 등록일시를 가진다. 등록자(소유자)는 두지 않는다(3단계에서 마이그레이션으로 추가).
- **영상 출처**는 "종류 + 값"이다. 1단계의 종류는 `UPLOADED_FILE`과 `EXTERNAL_URL` 두 가지다. 값은 업로드 파일이면 서비스가 정한 저장 이름(UUID + 확장자)이고, 외부 URL이면 그 주소다. 2단계에서 새 종류(예: 라이브 다시보기)를 추가할 수 있는 구조로 둔다.
- 제목 규칙: 앞뒤 공백을 제거한 뒤 1~100자. 녹화방송을 만드는 시점에 도메인이 이 규칙을 강제한다.
- 중복 제목, 중복 URL은 허용한다.

### 백엔드 모듈

- **녹화방송 모듈**: 녹화방송 등록, 목록 조회(등록일시 내림차순), 단건 조회를 제공하는 깊은 모듈. 웹 계층은 이 모듈의 인터페이스만 호출한다.
- **업로드 파일 저장소**: 파일 저장, 저장 이름으로 읽기(바이트 범위 포함)를 제공하는 인터페이스. 1단계 구현은 `RECORDING_STORAGE_DIR` 아래 로컬 디스크다(ADR-0001). 2단계에서 교체할 수 있도록 녹화방송 모듈은 인터페이스에만 의존한다.
- 등록 순서: 입력 검증 → 파일 저장 → 메타데이터 저장. 메타데이터 저장이 실패하면 방금 저장한 파일을 지운다.
- 외부 URL은 형식(`http`/`https`, 호스트 존재)만 검사하고 서버가 접속하지 않는다(ADR-0002).

### API 계약 (모두 인증 없음)

- `POST /api/recordings`: `multipart/form-data`. 필드 `title`(필수), `file`과 `url` 중 정확히 하나.
  - 성공: `201 Created` + `Location: /api/recordings/{id}` + 녹화방송 상세 본문.
  - 검증 실패(제목, 출처 개수, URL 형식, 파일 형식): `400` + RFC 9457 Problem Details. `errors` 배열에 `{ field, message }`를 담고, 메시지는 한국어로 쓴다.
  - 크기 초과: `413` + Problem Details.
- `GET /api/recordings`: 녹화방송 목록. 각 항목은 `id`, `title`, `sourceType`, `createdAt`. 등록일시 내림차순이다. 1단계에는 페이지네이션이 없다.
- `GET /api/recordings/{id}`: `id`, `title`, `sourceType`, `videoUrl`, `createdAt`. `videoUrl`은 외부 URL이면 그 주소, 업로드 파일이면 `/api/recordings/{id}/video`다. 없으면 `404` + Problem Details.
- `GET /api/recordings/{id}/video`: 업로드 파일 스트리밍.
  - 일반 요청: `200`과 전체 파일.
  - `Range` 요청: `206 Partial Content`와 `Content-Range`. 범위를 만족할 수 없으면 `416`.
  - `Accept-Ranges: bytes`, `Content-Type`은 `video/mp4` 또는 `video/webm`이다.
  - 녹화방송이 없거나, 출처가 외부 URL이거나, 파일이 디스크에 없으면 `404`.
- `createdAt`은 ISO-8601 UTC로 내려주고, 화면에서 브라우저 로컬 시간으로 표시한다.

### 스키마

- PostgreSQL. 스키마는 Flyway로만 관리하고, 첫 마이그레이션이 녹화방송 테이블을 만든다.
- 녹화방송 테이블: 식별자(자동 증가 bigint), 제목(최대 100자, not null), 영상 출처 종류(not null), 영상 출처 값(text, not null), 등록일시(timestamptz, not null). 목록 정렬을 위해 등록일시 인덱스를 둔다.
- JPA의 스키마 자동 생성은 끄고 검증 모드(`validate`)로 둔다.

### 설정·환경변수

- `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`: PostgreSQL 접속 정보.
- `SERVER_PORT`: 백엔드 포트(기본 `8080`).
- `VITE_API_PROXY_TARGET`: 개발 실행 시 Vite가 `/api`를 넘길 백엔드 주소(기본 `http://localhost:8080`).
- `RECORDING_STORAGE_DIR`: 업로드 파일 보관 폴더(기본 `./data/uploads`). 없으면 시작할 때 만든다.
- `RECORDING_MAX_UPLOAD_SIZE`: 최대 업로드 크기(기본 `500MB`). Spring multipart 한도와 프론트 앞단 프록시의 요청 본문 한도에 같은 값이 적용되어야 한다.
- 루트에 `.env.example`로 예시를 제공한다.

### 프론트엔드

- React + Vite + TypeScript SPA. 라우팅은 React Router, 통신은 `fetch`를 감싼 얇은 API 클라이언트 하나. 상태관리 라이브러리는 쓰지 않는다.
- 화면:
  - 목록 `/`: 최신순 목록, 빈 상태 안내와 등록 버튼.
  - 등록 `/recordings/new`: 제목, 출처 종류 선택(업로드 파일/외부 URL), 선택한 종류의 입력란. 클라이언트에서도 제목, 출처, URL 스킴, 파일 형식을 검사하지만 최종 판단은 서버가 한다. 업로드 중에는 등록 버튼을 비활성화하고, 성공하면 상세로 이동한다. 서버의 Problem Details `errors`를 필드별로 표시한다.
  - 상세 `/recordings/:id`: 제목, 등록일시, `<video controls>` 플레이어(`src` = `videoUrl`). 재생 오류 이벤트가 나면 안내 문구를 보여 준다. 404면 "찾을 수 없음"과 목록 링크를 보여 준다.
- 공통 헤더에 목록과 등록 링크를 둔다.
- 개발 시 Vite 개발 서버가 `/api`를 백엔드로 프록시하므로 CORS 설정이 필요 없다.

### 실행·배포

- 루트에 `backend/`, `frontend/`, `docker-compose.yml`, `README.md`를 둔다.
- `docker compose up --build`: PostgreSQL, 백엔드, 프론트(정적 빌드를 서빙하고 `/api`를 백엔드로 프록시하는 웹 서버)를 띄운다. DB 데이터와 업로드 폴더는 이름 있는 볼륨으로 유지해서 `docker compose down` 후 다시 올려도 남는다(`down -v`일 때만 지워진다).
- 개발 실행: DB만 compose로 띄우고, 백엔드는 Gradle wrapper로 `bootRun`, 프론트는 `npm run dev`로 실행한다.
- 백엔드: Spring Boot 4.1.x, Kotlin, JDK 21, Gradle Kotlin DSL.

## Testing Decisions

- 좋은 테스트는 외부에서 관찰 가능한 동작만 검증한다. 내부 클래스 구조, 호출 순서, 리포지토리 호출 여부는 검증하지 않는다. 리팩터링으로 구조를 바꿔도 동작이 같으면 테스트는 그대로 green이어야 한다.
- 모든 기능과 버그 수정은 red → green → refactor로 진행하고, 사이클마다 `docs/tdd-log.md`에 기록한다.
- **경계 1: 백엔드 HTTP API.** Spring Boot 앱 전체를 띄우고, Testcontainers의 실제 PostgreSQL과 테스트마다 다른 임시 업로드 폴더를 쓴다. 테스트는 REST API만 호출하고, 응답과 이후 조회 결과로 검증한다. 다루는 범위:
  - 업로드 파일 등록과 외부 URL 등록, 등록 후 목록·상세 조회
  - 검증 실패 400: 제목 공백·초과, 출처 없음·둘 다, URL 스킴, 파일 형식. 크기 초과 413.
  - 목록의 최신순 정렬, 없는 id 404
  - 업로드 영상 스트리밍: 전체 200, Range 요청 206과 정확한 바이트 범위, 범위 밖 416, 외부 URL 출처의 video 요청 404
  - 메타데이터가 DB에 저장되어 새 요청에서 조회됨
- **경계 2: 프론트 앱 화면 단위.** 라우터를 포함한 앱 전체를 Vitest + React Testing Library로 렌더링하고, 네트워크 경계인 전역 `fetch`만 `vi.stubGlobal`로 스텁한다. 화면에 보이는 텍스트와 사용자 동작으로만 검증한다. 다루는 범위:
  - 목록 표시와 빈 상태
  - 등록 폼: 출처 종류 전환, 클라이언트 검증 메시지, 업로드 중 버튼 비활성화, 성공 시 상세로 이동, 서버 400 오류의 필드별 표시
  - 상세: 플레이어 `src`, 재생 오류 안내, 404 안내
- 이 두 경계로 확인할 수 없는 것(실제 브라우저 재생, 탐색, 프로세스 재시작 후 유지)은 README의 직접 확인 절차로 검증한다.
- 테스트를 실행하려면 Docker가 필요하다(Testcontainers). README에 적는다.
- 아직 코드가 없어 참고할 기존 테스트는 없다. 이 단계에서 만드는 테스트가 2~4단계 테스트의 기준이 된다.

## Out of Scope

- 녹화방송 수정, 삭제, 검색, 페이지네이션, 썸네일
- 외부 URL의 재생 가능 여부를 서버가 확인하는 기능(ADR-0002)
- 유튜브 같은 플랫폼 링크, HLS/DASH 스트리밍 주소
- mp4/webm 이외 형식, 서버 쪽 트랜스코딩
- 로그인, 등록자 표시, 권한(3단계)
- 라이브 방송 송출(2단계), 댓글(3단계), 도네이션(4단계)
- E2E 자동화 테스트
- 업로드 이어 올리기, 진행률 표시

## Further Notes

- 용어는 `GLOSSARY.md`를 따른다: 녹화방송, 제목, 영상 출처, 업로드 파일, 외부 URL. 코드 식별자는 영어 대응어(Recording, Title, VideoSource, UploadedFile, ExternalUrl)를 쓴다.
- 관련 결정: ADR-0001(로컬 디스크 + Range 스트리밍), ADR-0002(외부 URL 서버 확인 안 함).
- README에는 실행 방법(전체 compose, 개발 실행), 환경변수 예시, 구현 범위(위 Out of Scope 포함), 직접 확인 절차를 쓴다. 직접 확인 절차는 "업로드 파일과 외부 URL 각각 등록 → 목록 확인 → 상세에서 재생·탐색 → 재시작 → 목록·재생이 유지되는지 확인" 순서다. 최종본 기준으로 계속 갱신하고 "단계별 구현 내역" 섹션을 둔다.
- 1단계를 마치면 `docs/presentation-notes.md`의 1단계 "결과·수치"와 "어려웠던 점"을 채운다.
- 개발 환경에는 아직 JDK가 설치되어 있지 않다. 구현 전에 JDK 21(Temurin)을 설치해야 한다.
