# 06: README와 1단계 마무리

**What to build:** 채점자가 README만 보고 서비스를 실행하고, 무엇이 구현되었는지 알고, 요구사항을 직접 검증할 수 있다. 이 티켓은 02~05가 모두 합쳐진 상태에서 아래 절차를 **순서대로** 진행한다. 앞 단계가 통과하지 않으면 다음 단계로 넘어가지 않고, 문제를 해당 티켓의 버그로 고친 뒤 처음부터 다시 진행한다. 스펙: `.scratch/recordings/spec.md`.

**Blocked by:** 02, 03, 04, 05

**Status:** ready-for-agent

### 1. 통합 상태 확인
- [ ] 02~05의 수용 기준이 모두 체크되어 있다
- [ ] 백엔드와 프론트의 전체 테스트가 green이다

### 2. 깨끗한 환경에서 실행
- [ ] 기존 컨테이너와 볼륨을 지우고(`down -v`) `docker compose up --build`로 띄운다
- [ ] 이때 실제로 친 명령과 접속 주소를 그대로 기록해 둔다(3단계 README의 원본)

### 3. 직접 확인 절차를 실제로 수행
아래 순서로 직접 해 보고, 단계마다 무엇을 보면 통과인지 기록한다.
- [ ] 빈 목록 안내가 보인다
- [ ] 외부 URL로 녹화방송을 등록 → 상세로 이동 → 재생된다
- [ ] 업로드 파일(mp4)로 녹화방송을 등록 → 상세로 이동 → 재생되고 탐색된다
- [ ] 목록에 두 녹화방송이 최신순으로, 출처 종류와 함께 보인다
- [ ] 잘못된 입력(빈 제목, 출처 없음, `ftp://` URL, 허용되지 않은 형식)에서 안내가 보인다
- [ ] 없는 녹화방송 주소에서 "찾을 수 없음"이 보인다
- [ ] `docker compose down` → `up` 후 두 녹화방송이 목록에 남아 있고 둘 다 재생된다

### 4. README 작성
3단계에서 기록한 것을 그대로 옮긴다. 수행하지 않은 절차는 적지 않는다.
- [ ] 소개와 단계별 구현 내역(1단계 완료, 2~4단계 예정)
- [ ] 실행 방법: 전체 compose(채점용)와 개발 실행(DB만 compose + `bootRun` + `npm run dev`), 필요한 도구(Docker, 개발 시 JDK 21·Node)
- [ ] 환경변수 예시: `.env.example` 내용과 각 변수 설명
- [ ] 구현 범위와 범위 밖(스펙의 Out of Scope, ADR-0002의 외부 URL 한계 포함)
- [ ] 직접 확인 절차: 3단계 순서 그대로
- [ ] 테스트 실행 방법과 Docker 필요 조건

- [ ] `docs/presentation-notes.md` 1단계의 "결과·수치"(테스트 수 등, 스크린샷 위치)와 "어려웠던 점·배운 점"을 채운다
