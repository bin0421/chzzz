# 02: 등록 검증과 오류 표시

**What to build:** 등록자가 규칙에 맞지 않는 녹화방송을 등록하려 하면 서버가 거절하고, 등록 화면이 그 이유를 필드별로 보여 준다. 클라이언트도 같은 규칙으로 미리 안내하지만 최종 판단은 서버가 한다. 스펙: `.scratch/recordings/spec.md`.

03(업로드 파일)과 병행한다. 03은 파일 관련 규칙(형식, 크기)을 맡고, 이 티켓은 제목·출처 개수·URL 규칙을 맡는다. 등록 폼에서는 제목과 URL 입력란, 오류 표시 부분만 건드린다.

**Blocked by:** 01

**Status:** resolved

- [x] 제목은 앞뒤 공백을 제거해서 저장한다
- [x] 공백 제거 후 제목이 0자이거나 100자를 넘으면 `400`(`errors`에 `title`)

- [x] 오류 메시지는 한국어다
- [x] 위 규칙이 백엔드 HTTP API 경계 테스트로 검증된다
- [x] 등록 화면이 같은 규칙의 클라이언트 검증 메시지를 보여 주고, 서버 `400`의 `errors`를 필드별로 보여 준다(앱 단위 테스트)

## Comments

- 출처 개수 오류의 필드 이름은 `source`다. 파일만 있는 요청은 03이 구현하기 전까지 `file` 필드 400("업로드 파일 등록은 아직 지원하지 않습니다.")으로 거절하며, 03이 `RecordingService.register`의 그 분기를 업로드 등록으로 바꾼다.
- 프론트 등록 화면은 `title`·`url` 오류를 입력란 옆에, 그 밖의 필드 오류(`source`, 03 전에는 `file`)를 폼 위 알림에 보여 준다. 03에서 파일 입력란을 붙이면 `INPUT_FIELDS`에 `file`을 더하고 그 옆에 표시하면 된다.
