# 02: 등록 검증과 오류 표시

**What to build:** 등록자가 규칙에 맞지 않는 녹화방송을 등록하려 하면 서버가 거절하고, 등록 화면이 그 이유를 필드별로 보여 준다. 클라이언트도 같은 규칙으로 미리 안내하지만 최종 판단은 서버가 한다. 스펙: `.scratch/recordings/spec.md`.

03(업로드 파일)과 병행한다. 03은 파일 관련 규칙(형식, 크기)을 맡고, 이 티켓은 제목·출처 개수·URL 규칙을 맡는다. 등록 폼에서는 제목과 URL 입력란, 오류 표시 부분만 건드린다.

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 제목은 앞뒤 공백을 제거해서 저장한다
- [ ] 공백 제거 후 제목이 0자이거나 100자를 넘으면 `400`(`errors`에 `title`)
- [ ] `file`과 `url`이 둘 다 없거나 둘 다 있으면 `400`(`errors`에 출처 관련 필드)
- [ ] `url`이 `http`/`https`가 아니거나 호스트가 없으면 `400`(`errors`에 `url`). 서버는 그 주소에 접속하지 않는다(ADR-0002)
- [ ] 같은 제목·같은 URL의 중복 등록은 성공한다
- [ ] 오류 메시지는 한국어다
- [ ] 위 규칙이 백엔드 HTTP API 경계 테스트로 검증된다
- [ ] 등록 화면이 같은 규칙의 클라이언트 검증 메시지를 보여 주고, 서버 `400`의 `errors`를 필드별로 보여 준다(앱 단위 테스트)
- [ ] 모든 사이클이 `docs/tdd-log.md`에 기록되어 있다
