# 04: 송출·시청 화면 마무리

**What to build:** 송출자는 휴대폰에서 방송 전에 전면·후면 카메라를 골라 미리보기로 확인하고, 문제가 생기면(권한 거부, 기기 없음, HTTPS가 아님, 연결 실패) 무엇을 해야 하는지 안내받는다. 방송 중에는 시청 화면 링크를 볼 수 있다. 시청자는 자동재생으로 소리가 막히면 "소리 켜기" 버튼으로 소리를 켜고, 연결이 실패하거나 없는 라이브 방송이면 안내를 받는다. 스펙: `.scratch/live-broadcasts/spec.md`.

02, 03, 05와 병행한다. 이 티켓은 **화면 쪽 사용성**을 맡고 백엔드는 건드리지 않는다. 송출 화면의 종료 버튼·키 보관(02)과 시청 화면의 종료·대기 처리(02, 03)는 건드리지 않는다.

## Comments

- 테스트는 새 파일 `frontend/src/LiveBroadcastScreens.test.tsx`(14개)에 두고, 기존 `LiveBroadcast.test.tsx`는 건드리지 않았다. 프론트 전체 37개 green, `npm run build`·`npm run lint` 통과. 백엔드는 바꾸지 않았고 `./gradlew test`도 통과.
- 미디어 어댑터 인터페이스를 넓혔다(02·03 병합 시 확인):
  - `MediaAccessError`(`reason`: `permission-denied` / `no-device` / `insecure-context`)를 `MediaAdapter.ts`에 추가했다. 실제 어댑터는 보안 컨텍스트가 아니거나 `navigator.mediaDevices`가 없으면 `insecure-context`, `NotAllowedError`·`SecurityError`는 `permission-denied`, `NotFoundError`·`NotReadableError`·`OverconstrainedError`는 `no-device`로 바꾼다.
  - `startPlayback(video): Promise<'audible' | 'muted'>`를 추가했다. 자동재생 거부(`video.play()`의 `NotAllowedError`)는 브라우저 미디어 API라서, "가짜는 `fetch`와 미디어 어댑터만" 규칙을 지키려고 어댑터에 넣었다. 시청 플레이어는 `autoPlay` 속성 대신 이 메서드로 재생한다. 가짜 어댑터 기본값은 `'audible'`.
- 제목 규칙을 `frontend/src/titleRule.ts`(`validateTitle`)로 꺼내 녹화방송 등록과 송출 화면이 함께 쓴다(녹화방송 화면 동작은 그대로).
- 송출 연결 실패는 두 경우로 본다: `publish`가 실패할 때, 그리고 송출은 붙었지만 상태 확인 중 방송 중이 되기 전에 종료(03의 대기 시간 초과)로 바뀔 때. 후자는 송출을 멈추고 같은 안내를 보여 준다. 03이 없으면 대기에서 계속 상태를 확인한다.
- 카메라를 바꾸면 이전 스트림의 트랙을 모두 끈 뒤 새로 연다(휴대폰은 두 카메라를 동시에 못 연다). 미리보기 거울 표시는 전면 카메라일 때만 한다.
- 방송 중 화면(`phase === 'live'`)에 시청 화면 링크를 넣었다. 02의 종료 버튼도 같은 자리에 들어가므로 병합 때 충돌이 난다. 둘 다 남기면 된다.
- 시청 화면의 상태별 분기(대기·종료·폴링)는 02·03 몫이라 만들지 않았다. 이 티켓은 404, 상세 불러오기 실패, `watch` 실패, 소리 켜기만 넣었다.
- 실제 브라우저 확인(PC, 웹캠 없음, 375px 폭): `/live/new`에서 실제 어댑터가 `NotFoundError`를 "카메라나 마이크를 찾지 못했습니다" 안내로 바꾸는 것과, 폼·안내가 휴대폰 폭에서 무너지지 않는 것을 봤다.
- 남은 것(06 휴대폰 확인): 권한 거부·HTTP 접속 안내, 전면/후면 전환, 시청 PC에서 자동재생 소리 막힘 → "소리 켜기".
