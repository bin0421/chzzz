## Comments

### 2. 깨끗한 환경에서 실행 (2026-11-10)

- LAN IP: `ipconfig`의 Wi-Fi/이더넷 IPv4 `192.168.0.5`(26.x는 VPN, 172.28.x는 WSL 가상 어댑터라 제외). `.env.example`을 `.env`로 복사하고 `PUBLIC_HOST=192.168.0.5`만 바꿨다.
- 실행한 명령: `docker compose down -v` → `docker compose up --build -d --wait`. db·mediamtx·backend·frontend·caddy 다섯 개 healthy.
- 접속 주소: 휴대폰·PC `https://192.168.0.5:8443`, PC `http://localhost:3000`.
- PC 확인: HTTPS 홈 200, `/internal/mediamtx/auth` 404. ffmpeg WHIP 송출(컨테이너 안)로 대기 → 방송 중 → 송출 끝 → 끊김 훅으로 종료. 영상이 오지 않은 대기 방송은 60초 뒤 종료. 상세 응답에 송출 키 없음.
  - 주의: ffmpeg의 `-authorization`에는 키만 넣는다(ffmpeg가 `Bearer `를 붙인다). 붙여서 주면 401.

### 3. 휴대폰 직접 확인 (2026-11-10, Android Chrome 송출 + PC 시청)

- 접속·인증서 경고: `https://192.168.0.5:8443/live/new` → "연결이 비공개로 설정되어 있지 않습니다" → 고급 → "192.168.0.5(안전하지 않음)(으)로 이동". 카메라·마이크 허용 후 전면 미리보기, 후면 전환 확인.
- 송출 → 시청: 휴대폰 "방송 중" → PC 목록 "방송 중" 배지 → 시청 화면 재생(휴대폰 세로 720×1280, VP8 + Opus, 소리 나옴). 지연은 사용자 체감 "거의 없음".
- 종료 버튼: 방송 4("111") 37초 방송 중 → 휴대폰에서 종료 → PC 시청 화면 "방송이 종료되었습니다"와 시작·종료 시각, 목록 "종료" 배지.
- 탭 닫기: 방송 6("0000") 송출 중 휴대폰 탭을 닫음 → PC 재생이 먼저 멈추고, MediaMTX가 연결 끊김을 알아챈 약 30초 뒤 끊김 훅으로 종료(00:19:43). 시청 화면·목록 모두 종료로 바뀜.
- 재시작: 대기 방송 7을 만든 직후 `docker compose down` → `docker compose up -d --wait`. 기록 7개가 모두 남고 대기였던 7은 종료로 정리됨.
- 1단계 회귀(같은 전체 실행): 빈 목록, 외부 URL 등록 → 상세 재생(브라우저), 업로드 파일 등록 → 재생·12초 위치로 탐색, `/recordings/9999` 찾을 수 없음, 재시작 뒤 두 녹화방송 유지와 업로드 영상 Range 206. 업로드 등록은 앱 브라우저 패널에서 파일 선택을 할 수 없어 화면과 같은 multipart 요청을 스크립트로 보냈다. 잘못된 입력 안내(5번)는 자동 테스트로 확인되는 범위라 이번에는 다시 하지 않았다.
- 스크린샷: 사용자 휴대폰 화면 캡처가 고장으로 불가해 PC 화면만 `docs/screenshots/stage-2/`에 남겼다(목록 방송 중, 시청 재생, 시청 종료, 목록 종료).
