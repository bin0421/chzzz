# 06: 휴대폰 확인, README, 2단계 마무리

**What to build:** 채점자가 README만 보고 휴대폰을 연결해 라이브 방송을 송출하고 다른 화면에서 시청·종료를 확인할 수 있다. 이 티켓은 02~05가 모두 합쳐진 상태에서 아래 절차를 **순서대로** 진행한다. 앞 단계가 통과하지 않으면 다음 단계로 넘어가지 않는다. 문제는 해당 티켓의 버그로 고친 뒤 처음부터 다시 진행한다. 3단계는 휴대폰 조작과 방화벽 허용이 필요하므로 **사용자와 함께** 진행한다. 스펙: `.scratch/live-broadcasts/spec.md`.

**Blocked by:** 02, 03, 04, 05

**Status:** ready-for-human

### 1. 통합 상태 확인
- [ ] 02~05의 수용 기준이 모두 체크되어 있다
- [ ] 백엔드와 프론트의 전체 테스트가 green이다(1단계 테스트 포함)
- [ ] 각 티켓의 `## TDD 기록`을 `docs/tdd-log.md`에 옮겼다

### 2. 깨끗한 환경에서 실행
- [ ] PC의 LAN IP를 확인하고 `.env`에 `PUBLIC_HOST`를 넣는다
- [ ] 사용자가 방화벽 허용 명령을 실행한다(`HTTPS_PORT`/TCP, `WEBRTC_PORT`/UDP·TCP). 에이전트는 명령만 안내한다
- [ ] 기존 컨테이너와 볼륨을 지우고(`down -v`) `docker compose up --build`로 띄운다. 실제로 친 명령과 접속 주소를 기록한다

### 3. 휴대폰 직접 확인 (사용자와 함께, Android Chrome 송출 + PC Chrome 시청)
- [ ] 휴대폰을 같은 Wi-Fi에 연결하고 `https://{PUBLIC_HOST}:{HTTPS_PORT}`에 접속한다. 인증서 경고를 넘기는 화면과 방법을 기록한다
- [ ] 송출 화면에서 카메라를 고르고 권한을 허용하면 미리보기가 보인다
- [ ] 방송 시작 → 휴대폰에 "방송 중"이 보인다
- [ ] PC 방송 목록에 "방송 중" 배지가 보이고, 시청 화면에서 영상과 소리가 나온다. 지연을 대략 기록한다
- [ ] 휴대폰에서 방송 종료 → PC 시청 화면에 "방송이 종료되었습니다", 목록에 "종료" 배지가 보인다
- [ ] 새 방송을 시작한 뒤 휴대폰 탭을 닫는다 → 자동 종료된다
- [ ] 전체 서비스를 재시작해도 라이브 방송 기록이 남고, 남은 방송 중·대기가 종료로 정리된다
- [ ] 1단계 녹화방송 직접 확인 절차(등록, 목록, 상세, 재생)가 그대로 통과한다

### 4. README 작성
3단계에서 실제로 수행하고 기록한 것만 옮긴다.
- [ ] 단계별 구현 내역 갱신(2단계 완료)
- [ ] 휴대폰 연결: 같은 Wi-Fi, LAN IP 확인 방법, `PUBLIC_HOST`, 방화벽 허용 명령, 인증서 경고 넘기기(Android Chrome, iOS Safari)
- [ ] 카메라·마이크 권한: 허용 방법, 거부했을 때 다시 켜는 방법(Android Chrome, iOS Safari)
- [ ] 로그인 없이 송출·시청하는 구성과 송출 키 설명
- [ ] 송출 시작·종료 확인 방법과 직접 확인 절차(3단계 순서 그대로)
- [ ] 실행 방법(전체, 개발), 새 환경변수 예시, 구현 범위와 범위 밖(스펙의 Out of Scope, ADR-0003의 같은 네트워크 한계 포함)
- [ ] 1단계 내용(녹화방송)은 그대로 유지한다

### 5. 2단계 기록 마무리와 제출
- [ ] `docs/tdd-log.md`에 2단계 사이클이 빠짐없이 있다
- [ ] `docs/presentation-notes.md` 2단계 섹션(목표, 주요 결정, 결과·수치, 어려웠던 점·배운 점)을 채우고, 확인 화면 스크린샷을 `docs/screenshots/stage-2/`에 저장한다
- [ ] 2단계 완성본을 커밋하고 `stage-2` 태그를 붙여 `origin`(https://github.com/bin0421/chzzz)에 `main`과 태그를 푸시한다. 사용자가 이 순서를 미리 요청했고, 실행 직전에 한 번 더 확인한다
