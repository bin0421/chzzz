# 05: 결제 성공·실패·취소·중복 직접 확인, README, 4단계 마무리

**What to build:** 채점자가 README만 보고 테스트 결제 성공·실패·취소와 승인 통지 중복을 직접 확인할 수 있다. 이 티켓은 02~04가 모두 합쳐진 상태에서 아래 절차를 **순서대로** 진행한다. 앞 단계가 통과하지 않으면 다음으로 넘어가지 않고, 문제는 해당 티켓의 버그로 고친 뒤 처음부터 다시 한다. 3단계(직접 확인)는 결제창 조작과 휴대폰이 필요하므로 **사용자와 함께** 진행한다. 스펙: `.scratch/donations/spec.md`.

> **변경(2026-11-10, 01 진행 중 사용자 결정)**: 결제창(`payment()`, API 개별 연동 키) 대신 **결제위젯**(`widgets()`, 문서용 공개 키 `test_gck_docs_…`/`test_gsk_docs_…`)을 쓴다. 공식 샘플의 공개 결제창 키가 토스 샌드박스에서 401로 거절되기 때문이다(ADR-0007). 이 문서의 "결제창"은 위젯의 "결제하기"로 이어지는 카드사 테스트 결제 화면을 뜻하고, 후원 시작은 "서버가 주문을 만든다 → 그 금액으로 위젯을 그린다 → 결제하기" 순서다. 위젯은 카드 외 결제수단(간편결제·계좌이체)도 테스트로 보여 주지만 확인은 카드로 한다.

### 3. 결제 직접 확인 (사용자와 함께)
> 01에서 사용자는 테스트 결제창에 실제 카드 정보를 넣지 않기로 했다("실제로 결제되지 않는다는 말을 믿을 수 없다"). 아래에서 결제창을 끝까지 진행해야 하는 항목(성공·실패·라이브 후원)은 진행 전에 사용자에게 다시 묻고, 하지 않으면 카드 없이 할 수 있는 확인(위조 성공 요청 거절, 승인 통지 중복을 가짜 결제 키로 재현 등)과 자동 테스트로 대신한 사실을 README에 그대로 적는다.
- [ ] 성공: 회원 B가 회원 A의 녹화방송에 테스트 카드로 후원 → 확정 화면 → 내역·합계에 반영
- [ ] 실패: 결제창에서 실패를 만들어(01에서 확인한 방법) "후원에 실패했습니다", 내역·합계 그대로
- [ ] 취소: 결제창을 닫아 "후원을 취소했습니다", 내역·합계 그대로
- [ ] 라이브 방송: 휴대폰 A로 송출, PC B가 시청 화면에서 후원 → A 화면(또는 다른 창)의 내역·합계가 몇 초 안에 늘어남
- [ ] 거절: 자기 방송·소유자 없는 방송에는 버튼 없음, 비로그인은 로그인 안내, API로 직접 보내도 409/401
- [ ] 중복: 확정 결과 화면 새로고침, 같은 확인 요청 `curl` 반복, 같은 웹훅 `curl` 반복 → 합계가 한 번만 늘고, 통지 기록에 "이미 확정"이 남는다(DB 조회)
- [ ] 금액 위조: 성공 주소의 금액을 바꿔 확인 요청 → 거절, 적립 안 됨
- [ ] 1~3단계 직접 확인 절차의 핵심(녹화방송 재생, 휴대폰 송출·시청, 세 역할 권한, 댓글)이 그대로 통과한다
