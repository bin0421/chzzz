# 03: 승인 확인 검증과 실패·취소

**What to build:** 결제 후 돌아온 확인 요청을 서버가 규칙대로 검증한다. 금액이 다르면 승인 API를 부르지 않고 거절하고, 다른 회원의 주문, 사라진 방송·바뀐 소유자, 이미 실패·취소된 주문도 확정하지 않는다. 결제 서비스가 거절하면 실패, 승인 뒤 값이 맞지 않으면 확인 필요로 남기고, 통신이 끊기면 결제 대기로 두어 다시 시도할 수 있다. 결제창에서 취소하거나 실패하면 `/donations/fail` 화면이 서버에 알려 후원을 취소·실패로 바꾸고 결과를 보여 준다. 스펙: `.scratch/donations/spec.md`, 결정: ADR-0007.

02(시작 규칙·화면)와 병행한다. 04(중복 통지)는 이 티켓 다음에 같은 확정 규칙을 다듬는다.

## Comments

### 정한 것 (2026-11-11)

- **결제 서비스가 거절·불일치한 확인 요청의 응답은 `200`**이고 본문 `status`가 `FAILED`·`NEEDS_REVIEW`, 새 필드 `failure: { code, message }`에 이유가 담긴다. 요청 자체는 규칙대로 처리되었고 결과가 "확정 아님"이기 때문이다(스펙 API 계약의 응답에 `status`가 있는 이유). 서버가 결제 서비스를 부르기 전에 거절하는 경우만 4xx: 없는 주문 `404`, 다른 회원 `403`, 실패·취소·확인 필요 주문 `409`, 금액 위조 `400`(`errors[0].field = amount`), 방송 삭제·방송자 변경 `409`. 통신 실패는 `502`(새 `common.BadGatewayException`, Problem Details).
- 거절해도 후원 상태 변경(실패)과 통지 기록은 남아야 해서 `confirm`의 트랜잭션은 거절 예외(`NotFound`·`Forbidden`·`Conflict`·`FieldValidation`·`BadGateway`)에 되돌리지 않는다. 그 밖의 예외(서버 오류)는 되돌린다.
- 통지 기록: 서비스에 들어온 확인 요청은 모두 한 줄 남는다. 확정하면 `NEW_CONFIRMED`, 그 밖(404·403·409·400·결제 서비스 거절·확인 필요·502)은 `REJECTED`와 짧은 이유(`detail`). 502는 다시 시도할 수 있지만 그 요청은 처리되지 못했으므로 `REJECTED`로 둔다(04에서 결과 종류를 다듬으면 바꿀 수 있다). 비로그인(401)은 서비스에 닿지 않아 기록되지 않는다.
- 승인 응답이 `DONE`이 아니면 실패(`PAYMENT_NOT_DONE`), `DONE`인데 주문번호·금액이 다르면 확인 필요(`PAYMENT_MISMATCH`).
- 상태 불변식: `Donation`은 결제 대기에서만 실패·취소·확인 필요로 바뀐다. 확정된 후원은 바뀌지 않는다. 이걸 넣은 이유: 이 티켓에서 "결제 서비스 거절 → 실패"를 만들자, 확정된 후원의 성공 화면을 새로고침하면 실제 토스가 `ALREADY_PROCESSED_PAYMENT`로 거절해 확정이 실패로 덮이는 회귀가 생겼다(테스트로 재현 후 고침). 이미 확정된 후원에 승인 API를 다시 부르지 않는 것과 "이미 처리됨 → 조회"는 04가 한다.
- 실패 보고(`POST /api/donations/fail`): 결제 대기인 자기 주문만 바꾼다(`PAY_PROCESS_CANCELED` → 취소, 그 밖 → 실패, 코드·메시지 저장). 확정이면 `409`. 이미 실패·취소·확인 필요면 바꾸지 않고 `200`으로 현재 상태를 돌려준다(실패 화면 새로고침). 통지 기록에는 남기지 않는다(승인 통지가 아니므로).
- 프론트: `/donations/fail`은 서버 응답의 상태로 제목을 고르고(취소/실패), 실패면 주소의 `message`를 이유로 보여 준다. 서버가 실패 보고를 거절하면 `ActionErrorNotice`로 이유. `/donations/success`는 4xx면 이유(400은 필드 오류 메시지), 502와 네트워크 오류면 "다시 확인" 버튼, 200이라도 `FAILED`면 "후원에 실패했습니다", `NEEDS_REVIEW`면 "후원을 확정하지 못했습니다"와 `failure.message`.
