# 02: 후원 시작 규칙과 후원 영역 표시

**What to build:** 서버가 후원 시작 요청을 규칙대로 거절하고, 화면의 후원 영역이 역할과 방송에 맞게 보인다. 금액은 빠른 선택(1,000·5,000·10,000·50,000원)이나 직접 입력으로 고르며 1,000~1,000,000원 정수가 아니면 결제창을 열지 않는다. 비로그인은 로그인 안내를, 방송 소유자 자신과 소유자 없는 방송에서는 후원 버튼이 보이지 않는다. 라이브 방송 시청 화면(종료된 방송 포함)에도 후원 영역이 있고 3초마다 다시 불러온다. 스펙: `.scratch/donations/spec.md`.

03(승인 확인 검증·실패·취소)과 병행한다. 확인 흐름은 고치지 않는다.

> **변경(2026-11-10, 01 진행 중 사용자 결정)**: 결제창(`payment()`, API 개별 연동 키) 대신 **결제위젯**(`widgets()`, 문서용 공개 키 `test_gck_docs_…`/`test_gsk_docs_…`)을 쓴다. 공식 샘플의 공개 결제창 키가 토스 샌드박스에서 401로 거절되기 때문이다(ADR-0007). 이 문서의 "결제창"은 위젯의 "결제하기"로 이어지는 카드사 테스트 결제 화면을 뜻하고, 후원 시작은 "서버가 주문을 만든다 → 그 금액으로 위젯을 그린다 → 결제하기" 순서다. 위젯은 카드 외 결제수단(간편결제·계좌이체)도 테스트로 보여 주지만 확인은 카드로 한다.

## Comments

### 확인한 것 (2026-11-11)

- 백엔드: 새 파일 `DonationStartRulesApiTest`(시작 규칙)와 `DonationListRulesApiTest`(내역·합계). 금액은 요청 본문을 형식 그대로 받아 `DonationAmount.parse`가 정수(Int/Long)만 통과시킨다. `Long`으로 받으면 Jackson이 `1000.5`를 `1000`으로 잘라 받아들이고, `"천원"`은 `errors` 없는 400이 되기 때문이다. 대기·방송 중·종료된 라이브 방송과 녹화방송 모두 경계값 201, 위반 400, 소유자 없음·자기 방송 409("후원할 수 없는 방송입니다."), 없는 방송 404, 비로그인 401, CSRF 없음 403이고 거절 뒤 `donation`은 0행이다.
- 내역: 없는 방송이면 404(전에는 빈 목록 200). 결제 대기·실패·취소·확인 필요는 SQL로 직접 넣어(03 흐름과 무관하게) 합계·건수에서 빠지는 것을 확인했다.
- 프론트: 새 파일 `DonationRules.test.tsx`(금액·버튼 표시·서버 거절), `DonationLive.test.tsx`(라이브 시청 화면, 3초 폴링). 금액 규칙은 `donations/donationAmountRule.ts`. 라이브 시청 화면에는 `<DonationSection … pollMs={DETAIL_POLL_MS} />` 한 줄과 import만 더했다(댓글 위, 녹화방송 상세와 같은 순서).
- 확인 흐름(`confirm`, 성공·실패 화면)과 Flyway 마이그레이션은 건드리지 않았다. `DonationService`는 `start`와 `confirmedOf`만 고쳤다.
