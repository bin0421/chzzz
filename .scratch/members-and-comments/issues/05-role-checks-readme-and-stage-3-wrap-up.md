### 3-1. 세 역할 API 직접 호출 (HTTPS, 브라우저처럼 쿠키·CSRF 헤더를 다루는 스크립트)

비로그인·소유자 A·다른 회원 B가 각자 쿠키를 가진 채 `https://192.168.0.5:8443`에 상태 변경 API를 직접 불렀다. 36건 모두 기대와 같음.
- 녹화방송: 등록 비로그인 401 / A 201, CSRF 헤더 없음 403, 제목 수정·삭제 비로그인 401·B 403·A 200/204
- 댓글: 작성 비로그인 401 / A·B 201, 목록 비로그인 200, B 댓글 수정 비로그인 401·A(방송 소유자) 403·B 200, A 댓글 삭제 B 403·CSRF 없음 403·A 204
- 라이브 방송: 시작 비로그인 401 / A 201, 종료(송출 키를 실어도) 비로그인 401·B 403, 제목 수정 B 403·A 200, 대기 중 삭제 409, A 종료 200·다시 종료 409, 종료 후 B 댓글 201, 삭제 B 403·A 204, 삭제 후 댓글 목록 404
- 로그아웃 204 뒤 같은 쿠키로 등록 401

### 3-2. 화면 직접 확인 (사용자와 함께, 2026-11-10)

역할: 소유자 A = 사용자 휴대폰(Android Chrome)에서 가입한 `bin0`과 사용자 PC Chrome, 다른 회원 B = 앱 브라우저 패널에서 가입한 `시청자B`, 비로그인 = 같은 패널 로그아웃 상태.
- 휴대폰: 볼륨을 지워 인증서가 새로 만들어져 경고를 다시 넘김 → `/live/new`가 로그인 화면으로 보냄 → 회원가입 후 송출 화면으로 돌아옴 → 방송 시작 → 방송 중.
- 비로그인(PC): 목록 라이브 섹션에 "ii", 소유자 "bin0", 방송 중 배지. 시청 화면에서 휴대폰 영상 재생, 관리 버튼 없음, 댓글 자리에 "로그인하면 댓글을 쓸 수 있습니다. 로그인". (스크린샷 01, 02)
- 다른 회원 B(PC): 헤더 "시청자B님", 영상 재생, 제목 수정·방송 종료·삭제 버튼 없음. 댓글 작성 → 바로 목록에 나오고 자기 댓글에만 수정·삭제. (03, 04)
- 소유자 A가 다른 기기(PC Chrome)에서 로그인해 시청 화면의 "방송 종료" → 서버 종료(15:53:44 시작, 15:57:17 종료), B 화면도 "방송이 종료되었습니다"와 시각으로 바뀌고 B 댓글은 남음. B 화면에는 방송 삭제 버튼 없음, B가 API로 직접 `DELETE` → 403 "이 방송의 소유자만 할 수 있습니다.", 방송 그대로. (05)
- A가 PC에서 삭제 → 라이브 방송 행과 B의 댓글이 DB에서 함께 사라짐.
- 녹화방송: B가 로그인 상태로 외부 URL 녹화방송 등록 → 소유자에게만 수정·삭제 → 제목 수정 저장 → 로그아웃하면 같은 화면에 버튼 없음, 댓글은 로그인 안내. (06)
- 발견하고 고친 것: 제목 수정을 눌러도 입력란에 포커스가 가지 않음 → 녹화방송·라이브 제목 입력란 `autoFocus`(테스트 red → green, tdd-log #135).
- 확인하지 못한 것: 라이브 방송 댓글이 "다른 창에 몇 초 안에" 나타나는 것은 화면 두 개를 나란히 놓고 보지는 않았다(3초 폴링은 04의 앱 단위 테스트로 확인). 1·2단계 절차 중 업로드 파일 등록·탐색은 이번 실행에서 화면으로 다시 하지 않았다(자동 테스트와 2단계 확인으로 대신, 업로드 Range는 업그레이드 확인 때 206 확인).
