# 04: 방송별 댓글

**What to build:** 녹화방송 상세와 라이브 방송 시청 화면 아래에 그 방송의 댓글 목록이 보인다. 누구나 볼 수 있고 오래된 순이며, 라이브 방송은 3초마다 다시 불러온다. 로그인한 회원은 댓글을 쓰고, 비로그인은 작성란 대신 로그인 안내를 보며 API로 써도 `401`로 거절된다. 작성자는 자기 댓글을 수정("수정됨" 표시)·삭제하고, 다른 회원은 방송 소유자라도 `403`이다. 방송이 삭제되면 그 방송의 댓글도 지워진다. 스펙: `.scratch/members-and-comments/spec.md`.

02(녹화방송 수정·삭제)·03(라이브 방송 소유자)과 병행한다. 댓글 테이블, 작성자 검사 규칙, "방송 삭제됨" 이벤트는 01에 있다.

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] `GET /api/recordings/{id}/comments`, `GET /api/live-broadcasts/{id}/comments`: 공개, 오래된 순 전체 `[{ id, content, author: { id, nickname }, createdAt, updatedAt }]`. 방송 없음 `404`
- [ ] 같은 경로 `POST` JSON `{ content }`: 로그인하면 `201` 댓글. 비로그인 `401`, 방송 없음 `404`, 내용(공백 제거 1~500자) 위반 `400`(`errors`에 `content`). 종료된 라이브 방송에도 쓸 수 있다
- [ ] `PATCH /api/comments/{id}` JSON `{ content }`: 작성자면 `200`과 `updatedAt`. 비로그인 `401`, 없음 `404`, 다른 회원(방송 소유자 포함) `403`
- [ ] `DELETE /api/comments/{id}`: 작성자면 `204`. 같은 거절 규칙
- [ ] 거절 뒤 댓글이 그대로임을 조회로 확인하고, CSRF 토큰 없는 작성·수정·삭제는 거절된다
- [ ] "방송 삭제됨" 이벤트를 받으면 그 방송의 댓글을 모두 지운다(테스트는 이벤트를 직접 발행해 확인. 실제 삭제 API와의 연결은 05에서 병합 후 확인)
- [ ] 백엔드 HTTP API 경계 테스트가 비로그인·작성자·다른 회원 세 경우를 확인한다
- [ ] 프론트: 녹화방송 상세·라이브 시청 화면 아래 댓글 영역(닉네임, 작성 시각, "수정됨"). 로그인 시 작성란(입력 오류 안내), 비로그인 시 "로그인하면 댓글을 쓸 수 있습니다"와 `next` 로그인 링크
- [ ] 프론트: 작성자에게만 "수정"(인라인)·"삭제"(확인 후). 서버 `401`·`403`에 맞는 안내
- [ ] 프론트: 라이브 방송 댓글은 3초마다 다시 불러와 다른 사람의 댓글이 나타난다
- [ ] 새 테스트는 새 파일에 둔다. 1·2단계·01 테스트는 모두 green
- [ ] 모든 사이클이 기록되어 있다. 병행 중이라 `docs/tdd-log.md` 대신 이 파일의 `## TDD 기록`에 남기고, 병합할 때 옮긴다
