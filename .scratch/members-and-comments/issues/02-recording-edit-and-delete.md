# 02: 녹화방송 제목 수정·삭제 (소유자만)

**What to build:** 소유자가 자기 녹화방송 상세 화면에서 제목을 수정하고, 녹화방송을 삭제한다. 삭제하면 업로드 파일도 지워지고 목록으로 돌아가며, 댓글 정리를 위해 "방송 삭제됨" 이벤트가 발행된다. 다른 회원에게는 버튼이 보이지 않고 API를 직접 불러도 `403`, 비로그인은 `401`이다. 소유자 없는 기존 녹화방송은 아무도 수정·삭제할 수 없다. 스펙: `.scratch/members-and-comments/spec.md`.

03(라이브 방송 소유자)·04(댓글)와 병행한다. 댓글 테이블과 이벤트, 소유자 검사 규칙은 01에 있다.

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] `PATCH /api/recordings/{id}` JSON `{ title }`: 소유자면 `200` 상세(제목 규칙은 등록과 같음, 위반 `400`). 비로그인 `401`, 없음 `404`, 다른 회원·소유자 없는 방송 `403`. 거절 뒤 제목이 그대로임을 조회로 확인
- [ ] `DELETE /api/recordings/{id}`: 소유자면 `204`, 이후 상세 `404`. 업로드 파일이면 디스크의 파일도 지워진다. 같은 거절 규칙(`401`/`404`/`403`), 거절 뒤 그대로 남음
- [ ] 삭제하면 "방송 삭제됨"(녹화방송, 식별자) 이벤트가 발행된다(댓글 정리는 04가 받는다)
- [ ] CSRF 토큰 없이 수정·삭제하면 거절된다
- [ ] 백엔드 HTTP API 경계 테스트가 비로그인·소유자·다른 회원 세 경우를 모두 확인한다
- [ ] 프론트: 소유자에게만 상세 화면의 "수정"(제목 인라인 수정, 저장·취소, 오류 안내)과 "삭제"(확인 후 삭제, 목록으로 이동)가 보인다. 다른 회원·비로그인에게는 보이지 않는다
- [ ] 프론트: 서버가 `401`·`403`을 주면 로그인 안내·권한 없음 안내를 보여 준다
- [ ] 새 테스트는 새 파일에 둔다(병합 충돌 줄이기). 1·2단계·01 테스트는 모두 green
- [ ] 모든 사이클이 기록되어 있다. 병행 중이라 `docs/tdd-log.md` 대신 이 파일의 `## TDD 기록`에 남기고, 병합할 때 옮긴다
